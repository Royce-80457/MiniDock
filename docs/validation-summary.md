# 验证状态

当前功能版本：0.1.14。验证环境：Apple silicon、macOS 27.0.1、Xcode 27.1。0.1.10 用户反馈恢复较跟手、最小化仍不跟手，效果基本满意且本轮未观察到闪回，但最后仍因三次未最小化读数暂停，不能判定核心交互已完全通过。

## 已有实际证据

- 用户实际使用并确认 Safari、TextEdit、系统设置、iPhone 镜像的前台重复点击最小化行为。
- QQ、WeChat、用户测试的 ChatGPT 路径进程（bundle ID 为 com.openai.codex）、DeepSeek 有多次最小化请求成功及后续 AXMinimized=true 回读；用户反馈功能测试成功。
- 后台首次点击有放行日志，部分应用最小化后没有焦点窗口时也按原生路径放行；完整的多窗口/Space 切换体验尚未全部验收。
- TextEdit 启动文件选择界面缺少可用的最小化能力，实际被跳过；普通文稿窗口可进入增强路径。
- 辅助功能身份已由临时签名改为稳定的本机开发证书；用户重新授权后恢复。

## 修订与边界

- 窗口动画期间可能出现 AX 通信失败；回读只做最多三次读取，从不重发最小化。
- 不将系统级 AX 焦点缺失直接当作不同前台应用，须由目标 app 的 AXFrontmost=true 进一步确认；真实 PID 冲突仍拒绝。
- 偶发窗口失效/通信失败取消当前点击；持续故障、权限撤销、写入失败仍暂停。
- 0.1.6 修正全局命中测试返回 notImplemented 时错误暂停整个工具的问题；后续长期运行仍在验证。
- 0.1.7 接受连续点击的 clickCount >= 1，移除最小化后 500ms 冷却及激活后的固定等待；保留每次 down/up 的前台/同一窗口验证、手势检查及 Space/显示器过渡等待。不重试或延后执行因动画而跳过的点击。
- Xcode/单元测试通过只证明工程和规则检查可运行，不能证明所有系统交互已通过。

## 0.1.8 动画期间误暂停修正

- 用户的 0.1.7 实际日志表明：后台首次点击放行，第二次快速点击进入最小化；随后约 392ms 内三次全局 AX 焦点通信超时触发暂停。此前按失败次数判断未考虑点击频率。
- 点击查询的 cannotComplete 现在须至少三次、首末跨度至少两秒才按持续故障暂停；正常窗口检查成功会清零。权限撤销、tap 失效、写入失败及有限回读耗尽的停止策略保持不变。
- down 时先读取目标 app 的焦点窗口；无窗口时直接放行，不必继续查询全局焦点。焦点读取超时仍跳过当前点击，不把错误当作可操作证据，不补发操作。
- 新增用户日志时间序列、密集失败仍须满足持续时长、恢复后重新计时的回归测试；真实 Dock 连续点击仍待用户复测。
- 实际执行 17 项核心规则测试全部通过，Release 构建成功；尚不能据此判定动画期间的实际切换体验已通过。

## 0.1.8 未最小化与 0.1.9 时序实验

- 用户日志显示 ChatGPT 路径进程在一次第二击后，最小化写请求成功，约 259ms 时 AXMinimized=false；用户确认窗口一直显示、没有明显缩小。此为实际未生效，不能归结为通信超时误报；单次回读不能区分 Dock 竞争、应用未执行或状态尚未完成转换。
- 用户明确选择继续快速点击的公开 API 实验，并接受尚未解决的兼容性问题。
- 0.1.9 在 mouse-up 回调之后等待 50ms，再验证 down 保存的同一前台应用和窗口。新输入、Space/设置等变化、调度超过 200ms 均取消旧操作；每次至多一次写入。50ms 是待验证的实验参数，不是 Dock 完成事件处理的保证。
- 通过公开 CGEventSource 事件计数，在查询前后及回读结果应用前检查是否已有新输入，减少 tap 回调尚未处理新点击时的误操作；读取计数并非原子事务。
- false 读数与 cannotComplete 共用最多三次读取预算；false 后可继续只读确认，持续未确认、未知或致命错误仍暂停。无重写、无无限重试。
- 23 项核心规则测试实际通过，包括延后操作遇新输入/状态变化/过期须取消、false 转 true、持续 false、混合通信故障预算与未知/致命结果。测试不驱动真实 Dock，实际兼容性等待用户验收。
- Release 构建成功。仍使用公开 API、被动监听和一次 AX 写入；尚未以真实交互证明时序竞争已解决。

## 0.1.9 快速点击证据与 0.1.10 查询实验

- 用户以约 150–200ms 间隔连续点击；多数点击的 AXFocusedWindow 查询耗尽 50ms 并放行；部分候选在执行阶段因新输入取消，或全局 AXFocusedApplication 超时。成功写请求的 handoffElapsedMs 约 61–87ms，之后回读被新点击取消，无法据此确认最终最小化状态。未暂停不等于已达到跟手/可靠性要求。
- 已通过签名 app 的显式只读 audit 实际测量：静止前台 ChatGPT 的应用批量查询 AXFrontmost + AXFocusedWindow 用时不足 1ms，AXFrontmost=true 且有窗口。该窗口的 AXFocused=false，因此不采用依靠旧窗口缓存和此属性绕过焦点查询的路线。静止测量不代表动画期间也能响应。
- 0.1.10 改用一次目标应用批量查询取得前台证据及焦点窗口，并验证窗口 PID；不再在交互路径查询系统 AXFocusedApplication。down 和执行前都须 NSWorkspace 前台 PID 与 AXFrontmost=true 一致，窗口相同且符合原有资格。
- 取消 50ms 固定等待，改为 mouse-up 回调返回后下一轮主队列执行；仍保留新输入取消、200ms 过期、有限回读和失败暂停。此调度不保证 Dock 原生处理已完成，可能再次出现竞争；用户已接受公开 API 实验的兼容性限制。
- 诊断增加 app-snapshot 的阶段和耗时，用于区分批量读取仍超时与等待/资格检查造成的延迟。读不到可靠状态仍跳过，不排队重放点击，也不假定可按任意快的节奏切换。
- 24 项核心规则测试实际通过，Release 构建成功。应用批量快照的前台证据须为 true，后台/未知状态在规则测试中拒绝。真实快速交互尚待本轮复测。
